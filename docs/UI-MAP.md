# UI map (task R1)

Generated by the dev step `uimap,<json>,<md>` (`clr/src/dev.rs`) on the "ultimate" state (`dev/ultimate.steps`): every one of the 58 menus is shown with `swapMenu` and its visible elements are listed. The full element list (6,511 lines: path, kind, rectangle, anchoring, image mode, text length/size/alignment, selectable kind) is written locally (`local/ui-map.jsonl`, not published because it names the game's objects); this page is the published summary. Regenerate:
```
bash tools/clr.sh play <abs>/out/ngu /tmp/x.png "click,Start New Game" "click,PLAY" "do,<abs>/dev/ultimate.steps" "uimap,<abs>/local/ui-map.jsonl,<abs>/local/ui-map-summary.md"
```

## What it tells us for the responsive layout
- **Images: 2,308 of 3,452 are 9-sliced** (border + stretchable centre): panels, frames and buttons can be resized freely without distortion. 1,144 are simple images (icons, illustrations, item sprites).
- **Only 5 menus have a large simple image** (30 % or more of the menu): Adventure (`Background`), Augments (`Mask`), Bottomless Pit (`PitBlaze`), Beards (`FuManchu`), Holiday (`santaUUG`). Most are illustrations, not drawn layouts: the "baked drawing" problem is much smaller than feared.
- **Anchoring**: about 1,400 elements (mostly texts and panels) already stretch with their parent; 3,000+ images and all 960 buttons are point-anchored (fixed size and offset), as expected for a 960x600 design.
- **Automatic layout is rare**: 12 GridLayoutGroups, 1 VerticalLayoutGroup, 3 ContentSizeFitters; 20 ScrollRects (lists that can show more content when there is room, per decision 1 of `docs/VISION.md`).
- Interactive elements: 960 buttons, 104 sliders, 71 input fields, 20 scrollbars, 2 dropdowns, 1 toggle in the menus (plus the main columns, not counted here).
