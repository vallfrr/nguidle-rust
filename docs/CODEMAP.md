# Code map

This index covers first-party tracked Rust source files. The source file names identify their current module or executable. Run `python -B tools/check_codemap.py` to check coverage.

- `clr/src/achievements.rs` — Local progression for the installation's platform achievements.
- `clr/src/assets.rs` — Access to the prepared data: folder (PC) or single `ngu.pak` archive (Vita), + log.
- `clr/src/autoplay.rs` — Scripted player for benchmarks (`docs/VITA-60.md`): replays a scenario through the same inputs the console sends
- `clr/src/bcl.rs` — Native BCL/Unity layer: native types, structs, intrinsics.
- `clr/src/bcl_core.rs` — BCL intrinsics (System.*): strings, numbers, Math, collections, I/O.
- `clr/src/bcl_sys.rs` — System intrinsics: Regex, hashes, AES, memory streams, BinaryFormatter (real .NET wire format through `serial`).
- `clr/src/capi.rs` — The engine's C ABI for native hosts (documented per function): init, input, frame, triangle list, textures.
- `clr/src/code.rs` — Lowered (resolved) code of a method.
- `clr/src/console_mode.rs` — Gamepad-first presentation and console layout.
- `clr/src/cooking_score.rs` — Cooking score optimization used by the interpreter.
- `clr/src/desktop_layout.rs` — PC presentation rectangles. Game scripts keep their original RectTransforms.
- `clr/src/dotnet_random.rs` — Seeded System.Random sequence used by the original Mono runtime.
- `clr/src/dev.rs` — Script-driven development tools (designed for the assistant: text output, no manual clicks).
- `clr/src/dropdown.rs` — Dropdown interaction and selection behavior.
- `clr/src/focus.rs` — Finds reachable controls and moves controller focus.
- `clr/src/input.rs` — Pointer input (mouse / touch): UI raycast, hover, press, click, drag and drop, Slider, Toggle.
- `clr/src/layout.rs` — Unity UI automatic layout: VerticalLayoutGroup, HorizontalLayoutGroup, GridLayoutGroup, ContentSizeFitter.
- `clr/src/legacy_save.rs` — Reads and writes legacy game save structures.
- `clr/src/lib.rs` — Declares the interpreter library modules and public API.
- `clr/src/lower.rs` — Lowering: dotnetdll::Instruction -> Op (token resolution, 1 instruction = 1 op).
- `clr/src/main.rs` — Command-line entry point for interpreter and debugging scenarios.
- `clr/src/motion.rs` — Render-time motion. The authoritative UI and game state still update on their normal clocks.
- `clr/src/profile.rs` — Transforms the game layout for different screen profiles.
- `clr/src/program.rs` — Loading of a .NET assembly (dotnetdll) -> flat tables (types, fields, methods).
- `clr/src/render.rs` — Unity UI rendering: production of a quad list (backend independent) + software rasterizer (PC tests).
- `clr/src/save_slots.rs` — Local save screens. The game still owns serialization and progression.
- `clr/src/script.rs` — Scripted input scenarios (clicks, drags, waits) for game verification.
- `clr/src/serial.rs` — Serializes player and save data using the .NET BinaryFormatter format.
- `clr/src/ui.rs` — RectTransform layout (world positions in screen pixels, bottom-left origin).
- `clr/src/unity.rs` — Minimal Unity engine: GameObject/Transform/UI components, scene loading, life cycle.
- `clr/src/unity_api.rs` — UnityEngine.* / UnityEngine.UI.* / Steam / Kartridge intrinsics (stubs).
- `clr/src/value.rs` — Value model of the CIL interpreter (dynamic typing).
- `clr/src/vm.rs` — Virtual machine: type registry, calls, execution loop, exceptions.
- `crates/ngu-desktop/src/actions.rs` — High-level actions (keyboard, mouse, gamepad) applied to the game: focus navigation and confirmation.
- `crates/ngu-desktop/src/bin/ngu-window.rs` — Starts the desktop window executable.
- `crates/ngu-desktop/src/gl.rs` — Renders engine quads through the desktop GPU window.
- `crates/ngu-desktop/src/lib.rs` — Desktop shell: window, mouse, keyboard (and gamepad through the `pad` feature).
- `crates/ngu-desktop/src/pad.rs` — Handles Windows gamepad input and focus.
- `clr/src/bcl_core/collections.rs` — Collection and delegate intrinsics.
- `clr/src/bcl_core/foundation.rs` — LINQ, object, exception, and string intrinsics.
- `clr/src/bcl_core/numbers.rs` — Numeric conversion and math intrinsics.
- `clr/src/bcl_core/services.rs` — Time, randomness, filesystem, and enum intrinsics.
- `clr/src/save_slots/hosted.rs` — Saves leased from a host (a server, for example): lease requests, import and export.
- `clr/src/save_slots/storage.rs` — Save files, metadata, and autosave persistence.
- `clr/src/unity/schedule.rs` — Managed delayed invocations and coroutines.
- `clr/src/vm/specializations.rs` — Game-specific VM accelerators.
- `crates/cil-interp/src/lib.rs` — Host-independent frame execution and scalar arithmetic.
- `crates/ngu-prep/src/dirs.rs` — Per-system data folders for the application (`NGUIdleRustEngine`).
- `crates/ngu-prep/src/lib.rs` — Verifies the game against the SHA-256 manifest and copies it without touching the original.
- `crates/ngu-prep/src/pack.rs` — Writes the single-file archive the Vita reads.
- `crates/ngu-prep/src/bin/ngu-prepare.rs` — Developer command line for the two preparation jobs.
- `crates/ngu-prep/src/locate.rs` — Finds an installed game in Steam, Flatpak, Snap and CrossOver locations.
- `crates/ngu-prep/src/prepare.rs` — The PC and Vita preparation jobs: verify, copy, export, pack.
- `crates/ngu-prep/src/unity/assets.rs` — Exports textures, fonts, text assets and audio clip records.
- `crates/ngu-prep/src/unity/export.rs` — Writes the scene file, tag list and asset folders from the game data.
- `crates/ngu-prep/src/unity/image.rs` — Decodes Unity texture formats to RGBA and writes PNG.
- `crates/ngu-prep/src/unity/layout.rs` — Builds script field layouts from the game's assemblies using Unity's serialization rules.
- `crates/ngu-prep/src/unity/mod.rs` — Reads Unity 2019.4 serialized files (header, object table, references).
- `crates/ngu-prep/src/unity/scene.rs` — Builds the exported scene description and applies the port's interface adjustments.
- `crates/ngu-prep/src/unity/typetree.rs` — Reads Unity objects from their type layout into JSON.
- `crates/platform-api/src/lib.rs` — Platform interface: the engine trait, draw target, actions, fixed-step time and triangle batching.
- `crates/save-format/src/lib.rs` — Independent reader and writer for the MS-NRBF wire format.
- `clr/src/host_platform.rs` — Host tuning chosen at run time: file publication and background autosaves.
- `clr/src/save_slots/view.rs` — Construction and refresh of the save screens.
- `clr/src/unity_api/controls.rs` — Unity intrinsic dispatch for controls.
- `clr/src/unity_api/runtime.rs` — Unity intrinsic dispatch for runtime.
- `clr/src/unity_api/scene.rs` — Unity intrinsic dispatch for scene.
- `clr/src/unity_api/services.rs` — Unity intrinsic dispatch for services.
- `clr/src/unity/scene.rs` — Scene loading and deserialization.
- `clr/src/vm/instructions.rs` — VM instruction dispatch and evaluation-stack integration.
- `clr/src/session.rs` — Safe, documented host of the whole game: implements the platform interface (`Session`).
- `crates/platform-api/src/testing.rs` — Synthetic engine for testing a port without game files.
- `crates/ngu-headless/src/lib.rs` — Reference port: the host loop, scripts and reports against any engine.
- `crates/ngu-headless/src/main.rs` — Command line that runs the real game headless and prints what was drawn.

Non-Rust parts a port author needs: `templates/port/` (port template; `Cargo.toml.in` is renamed on generation so that cargo, which scans git dependencies for manifests, never sees a placeholder manifest; generated by `tools/new_port.py` and built by `tools/check_template.py`), `tools/nguprep.py` and `tools/pack.py` (game data preparation), `.claude/skills/nguidle-port/` (agent skill for porting).
