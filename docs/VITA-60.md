# Vita 60 Hz: scripted sessions, traces and the optimization loop

Goal: constant 60 Hz presentation on the PS Vita at the lowest clocks that hold it, with the game logic unchanged.
Method: replay the same real play session automatically, record every frame, let a script say where the time goes.
Nothing here needs a person (or a model) in the loop: one command per measurement, one short report per run.

## Pieces
| Piece | What it does |
| --- | --- |
| `clr/src/autoplay.rs` | Scenario reader. Injects the console's own inputs (`ngu_pad`, touch through `ngu_frame`, `ngu_scroll`) at given **simulation ticks** (30 per game second, independent of the frame rate, so a slow frame never reorders the session). Also the PC runner `clr <dll> autoplay <assets> <scenario> <trace.csv>`. |
| `clr/src/capi.rs` | `ngu_autoplay_load(path)`, `ngu_frame_info(out)` (tick, simulation steps, interpreted instructions, menu id, last action number, mark number, finished flag), `profile_report(top)`. |
| `nguidle-vita/scenarios/*.txt` | Generated by `tools/gen-scenarios.py` (deterministic, public, no game content): `tour` (all 58 menus, 5 s each, ~5 min), `session` (new game, 5 laps over 17 menus with buttons, D-pad, taps, stick, Save page, a save digest per lap, ~30 min), `monkey` (seeded random walk, 2 h). |
| `nguidle-vita/main.c` (benchmark build) | If `ux0:data/ngu/bench/scenario.txt` exists: loads it and writes `bench/trace.bin` (64 bytes per frame, written in chunks by a worker thread) then `bench/done.txt`. |
| `tools/vita-trace.py` | Summary of a trace (`.bin` from the console or `.csv` from PC): work per frame, presentation rate and late frames, worst phases, worst spikes with the scenario line that preceded them, spike periodicity, comparison with a saved baseline. |
| `tools/ngu-profile.sh <scenario>` (WSL) | PC replay + the trace summary + the top methods by exclusive interpreted instructions (hardware independent: what to optimize or translate to Rust). |
| `tools/vita-cycle.sh <scenario> [label]` (WSL) | Build, install if changed, upload, launch, wait for `done.txt`, download, analyze: the whole console measurement. |
| `tools/vita-batch.sh label:scenario[:VAR=val] ...` | Several cycles in a row, one comparison table at the end (overnight runs). |

## Scenario format (`clr/src/autoplay.rs`)
One event per line: `<tick> pad <chars>` (`u d l r` focus, `a` confirm, `b` back, `p n` previous/next menu, one per frame),
`touch <x> <y>`, `scroll <dx> <dy>`, `menu <n>`, `click <label text>`, `mark <name>`, `check <name>`, `ui` (debug: screen as text in the log), `end`.
`click` finds the visible control by its label, like the dev mode. A click with no matching control is logged (`[autoplay] click: no control`), not fatal.

## Trace record (16 little-endian u32)
`frame, t_us, work_us (no vsync wait), logic, layout, emit, draw, swap, upload, tick, steps, instr, menu, action, marks, flags`
(flags: 1 = scanout repeat seen, 2 = texture/atlas upload in the frame, 4 = scenario finished). Header `NGUT` + a count the host does not rewrite
(readers use the file size). `t_us` differences give the real presentation cadence: a gap above ~25 ms is a missed refresh.

## Commands
```sh
# PC, hardware independent (WSL): where the interpreted work goes
tools/ngu-profile.sh nguidle-vita/scenarios/tour.txt 20
# console, one run (needs VITA_AGENT, the Vita SDK, the data pack on the console)
tools/vita-cycle.sh session baseline          # then: cp out/vita-60/baseline/summary.json out/vita-60/baseline.json
# console, several variants unattended
tools/vita-batch.sh base:session fast:session:NGU_VITA_FAST_CLOCKS=ON monkey:monkey
```
A late-game measurement needs the late-game save: `FIXTURE=/path/NGUSaveSteam.txt tools/vita-cycle.sh tour late-tour`
(the benchmark build uses `bench/save` as its save folder).

## Rules for the optimization loop
1. Never optimize without a trace that names the cost. Read the short report; open raw files only when the verdict is bad.
2. One change set per measurement cycle; keep it only if p99 or late frames improve and the digests (`check`) do not change.
3. `tools/regress.sh` must stay `ALL OK`. Save digests are only comparable between runs with the same clock and save folder
   (the game stamps real time into a save), so compare them PC-to-PC with `NGU_FIXED_NOW` and Vita-to-Vita.
